## Chosen behavior

### Data source and backend handoff

Configuration lives in **`frontend/.env.local`**, documented by a new `frontend/.env.example`; a root `.env` is not automatically loaded by Vite running in `frontend/`.

| Variable | Default | Meaning |
| --- | --- | --- |
| `VITE_GIS_API_BASE_URL` | Existing `VITE_API_BASE_URL`, otherwise `http://localhost:5051` | GIS-specific override without changing diagnostics configuration |
| `VITE_GIS_PARCELS_PATH` | `/api/v1/spatial/geojson/parcels` | Read-only parcel FeatureCollection endpoint |
| `VITE_GIS_DATA_MODE` | `auto` | `auto`, `api`, or `sample`; reject other values as configuration errors |

When TODO-205 is ready, change `VITE_GIS_PARCELS_PATH` to `/api/v1/fields/<actual-field-id>/parcels` if it returns the documented GeoJSON FeatureCollection. Do not probe guessed routes or infer readiness from a health endpoint. Changing field selection dynamically is separate work; this task supports one configured collection.

| Condition | `auto` behavior |
| --- | --- |
| Valid successful FeatureCollection, including zero features | Show live data; an empty collection remains an honest empty state |
| API unreachable, request timeout after 5,000 ms, HTTP 404/501, or another HTTP 5xx | Show bundled samples with **“Sample data — live data unavailable”** and **“Retry live data”** |
| HTTP 401/403, 429, other HTTP 4xx, invalid JSON, or invalid parcel contract | Show an error with retry; do not replace it with samples |
| Caller abort from navigation/unmount or a superseding request | Stop silently; do not activate sample mode |

`api` mode never falls back. `sample` mode makes no API request and displays **“Sample data”**. A valid live collection displays **“Live data”**. Retrying replaces the collection atomically after validation; never combine live and sample parcels. Keep the previous map data visible while retrying and report the final outcome; an error must remain visible even if prior data is retained.

Use two deterministic, adjacent sample parcels inside one documented fictional farm in rural Türkiye, with UUID-shaped IDs and the same property names as the real feed. Make no claim that they represent real farm records. Offline parcel fallback does not make remote tile imagery available offline.

### Map and viewport

- Add `/map` and `/fields/:fieldId/parcels`; redirect `/field-map` to `/map`. Update desktop and mobile **Field GIS** links. Use a 64px top bar with source status, loaded parcel count, retry, and a field selector derived from loaded `field_id`/`field_name` properties. All fields navigates to `/map`; choosing one navigates to its scoped route and frames only its parcels. A scoped route with no matching records displays an honest empty state, not unrelated parcels.
- Display neutral Bio-Teal read-only parcel boundaries. Crop styling, persistent labels, selection drawer, and editing remain TODO-209/208 work.
- Default map center is `[39, 35]`, zoom `6`, when no parcel bounds exist. Valid parcels override this once loaded. Fit with 48px desktop padding, `maxZoom: 18`, `animate: true`, `duration: 0.8`; disable animation for reduced motion. Use asymmetric safe mobile padding so controls do not obscure the bounds.
- Fit only on first valid data load, a changed geometric extent, or explicit recenter. Preserve user pan/zoom during unrelated React renders, retries that return identical extents, resize, and basemap changes.
- Use one long-lived `MapContainer`. Import Leaflet CSS before map overrides. Height is `calc(100dvh - 64px)` with a `calc(100vh - 64px)` fallback, no desktop outer scrolling, and `min-width: 0` in flex/grid layouts. Accommodate short landscape viewports without forcing outer overflow.
- Observe container size with `ResizeObserver`, coalesce updates with `requestAnimationFrame`, and call `map.invalidateSize({ pan: false, debounceMoveend: true })` after positive dimensions. Cancel pending frames and disconnect observers on cleanup. Recheck size when a hidden container becomes visible.
- Use a scoped stacking context (`isolation: isolate`) so Leaflet panes cannot cover app navigation. Keep controls and attribution inside the map surface without overlapping on narrow screens or safe areas.
- Suppress raw Leaflet zoom buttons; use custom controls per SPEC-UI-008: segmented Satellite/Streets at top-right, vertical zoom/recenter dock bottom-right, coordinate and metric/imperial scale HUD bottom-left, North compass. Controls have selected state, focus styles, and 48px mobile hit targets. Keep overlays present across basemap switches. A noninteractive compass may remain 32px as specified.
- Esri: `https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/{z}/{y}/{x}`. Verify service native zoom limits and current attribution at implementation; use `maxNativeZoom` to overzoom existing imagery rather than request unavailable high-resolution levels.
- OSM: `https://tile.openstreetmap.org/{z}/{x}/{y}.png`, with visible OpenStreetMap contributor attribution. Respect provider caching; do not add bulk prefetch/offline tile downloading.
- Listen to active layer load/error events, reset status when changing layers, and keep a nonblocking tile-error message plus explicit Street switch available if satellite tiles fail. Do not automatically oscillate providers or block the parcel layer because a tile failed.

## Review focus

1. **Unavailable API versus valid empty data:** only defined availability failures enable sample fallback; authorization, malformed payloads, and cancellations must not look like successful sample loads.
2. **Coordinate and bounds correctness:** longitude/latitude order, polygon holes, MultiPolygons, zero coordinates, and empty collections must not frame the wrong location or crash.
3. **Resize and navigation lifecycle:** React StrictMode, orientation changes, hidden-to-visible containers, and route return must not leave gray tiles, duplicate map instances, or leaked observers.
4. **Async and user interaction:** a stale response must not replace newer data; changing basemap or resizing must not snap a panned map back to its original bounds.
5. **External tile availability and small screens:** source badges, error feedback, controls, keyboard access, and attribution remain usable even while the provider is unavailable.
